# MEMORY.md

Long-term curated memory for this agent/workspace.

- Typical project-edit workflow: for project file changes, follow this skill order when applicable: 1) run `project-auto-backup` first when feasible; if backup fails, stop and surface the error before editing. 2) Before planning or writing code, use `karpathy-guidelines` to review constraints, keep changes surgical, surface assumptions, and define narrow success checks. 3) Plan and implement according to applicable project conventions, using `project-file-organization` when creating a new project, adding/moving files, or reorganizing structure. 4) After creating, editing, or refactoring source code, use `project-code-cleanup` before the final response to preserve behavior, clean formatting/imports/comments, and run the narrowest useful checks. Skip this workflow for read-only tasks and non-project memory-only edits; skip cleanup for explicit no-edit requests and generated/vendor/minified/lock-file-only changes unless requested.
- When invoking skill scripts or tools that accept structured parameters, pass parameters as explicit JSON when the skill documentation shows JSON or does not require another format.
- All necessary code comments MUST be in Chinese (`// 中文内容注释`) unless preserving required license headers, generated-file notices, documentation format, or external project conventions.
- Scripting project line-count guidance: <200 lines keep as-is; 200+ watch for oversized responsibilities; 300+ requires structure review, not automatic splitting; 500+ prefer splitting unless strongly cohesive or high behavior risk; 800+ split unless it is generated-style data/config or a rare cohesive exception. Split when a file mixes types, constants, utilities, services, reusable components, and pages; keep cohesive complex pages, dense declarative UI, schema/config, or generated-style data together when clearer, and state the reason when leaving a touched 300+ line file unsplit.
- Run `project-file-organization`'s `scripts/check.py` when feasible after creating/reorganizing Scripting project files, or when a touched Scripting source file reaches 300+ lines. Use the result as review input, not as an automatic rewrite mandate.
